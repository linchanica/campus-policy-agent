## 日常本机操作

在项目目录执行 `./scripts/Start.ps1`，访问 http://127.0.0.1:8000。用 `./scripts/Stop.ps1` 停止本项目；脚本核验实际服务PID、启动时刻、项目目录和端口，不停止其他Python程序。重启时分别运行两个命令。

检查命令：`.venv/Scripts/python.exe -m app.cli doctor`；健康接口 `/health/live` 与 `/health/ready`；日志在 `work/server.err.log`。本地guest凭证不是学校身份，有效期24小时；可在试用说明中退出撤销或清空本人记录。自动保留清理仍待实施，试用请使用虚构资料。

修改.env或后端代码后重启服务；修改前端后分别运行两个build命令，并由使用者刷新网页。网页静态文件直接由FastAPI提供。服务器只绑定127.0.0.1，没有配置自动开机运行或公网暴露。

## 政策审核与补件

执行 `python -m app.cli review-export` 导出 `docs/policy-review-queue.json`。由业务人员核对每份副本的准确原网页、版本、学院学历范围、原文段落表格、各阶段日期、引用附件及编码条件。哈希通过只说明本地副本一致。雷军计算机奖学金完整材料清单和马院部分附件/文号仍待确认；官网抓取403不能证明附件不存在。

当前副本已超过部分原通知申报日期。演示开放窗口时，必须使用前端试用说明中的历史回放，并保留2026-10-24标识。正式咨询不得隐藏当前日期或补造延期。

## 更新与版本流程

1. 保留旧数据、源码、规则、提示、模型与索引的同批备份，在独立目录接收新原件。
2. 登记原网页、取得时间、校验哈希、替代关系和附件。当前ingest默认只重解析项目已有原件；`--archive`仅支持最初提供压缩包的结构映射，不能用于任意新数据集。
3. 修改结构化范围及规则草稿，逐项绑定原文，并补充会触发变化的评测题。
4. 由业务人员完成审核；未决事项维持unknown或转人工，不自动签署批准。
5. 为新快照建立同修订模型的索引，检查数量与片段ID一致性，运行规则、来源、权限与双端验收。
6. 当前发行版尚无在线原子发布、多版本原文管理和审核管理界面。这些技术模块需继续实现并验证后，才能执行正式快照切换。
7. 切换前确认在途任务的旧版本归属与历史出处可读，保留上一快照。
8. 观察真实错误率与业务反馈，达到回滚条件时恢复同批代码、规则、数据与索引，再重新验证关键问题。

## 备份恢复

执行 `python -m app.cli backup`，保存一致SQLite备份、原件、标准文本、规则源码、前端构建与向量快照，生成文件哈希清单。备份不含.env密钥、模型权重、虚拟环境和node_modules。

执行 `python -m app.cli restore-check`，复制到隔离目录，检查数据库完整性及外键、原件哈希、标准文本、向量维度，并从恢复源码运行doctor。不会覆盖当前运行目录。报告在 `docs/verification/restore_check.json`。模型需按固定修订另行恢复；正式环境的身份与整套咨询验收不能仅用doctor替代。

## 网页和小程序接续

1. 落实服务器、域名、证书、预算和正式身份。先完成当前仍缺的生产配置、自动保留清理、管理审核与发布模块。不要仅解除APP_ENV=production阻断后宣称上线。
2. 接入学校允许的模型或评测合格的本地模型，完成结构化画像与复杂政策的专项评测。当前0.5B模型只做原文候选选择，相关性与理解能力有限。
3. 部署API、Worker、数据和索引，并通过HTTPS代理提供网页及API。设置准确CORS来源，后台密钥不进入VITE变量或小程序代码。
4. 由账号持有人完成微信平台登录并取得AppID、开发者权限。在 `frontend/student/src/manifest.json` 填真实mp-weixin.appid，将前端环境配置为手机可达的HTTPS API地址，重新构建。
5. 在微信平台按实际控制台要求配置网络域名、类目和隐私等事项。用开发者工具导入 `frontend/student/dist/build/mp-weixin`，先验证模拟器，再检查手机真机、附件、登录、多轮修正与错误恢复。
6. 实际上传后记录体验版版本与体验人员，完成体验测试，再提交平台审核。只有审核通过并发布、正式入口复测后，才能登记为正式上线。
