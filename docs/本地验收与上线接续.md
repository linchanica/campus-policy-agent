# 本地验收与上线接续

本项目目录：`outputs/policy-agent`。以下命令在该目录运行。先完成本地验收，再落实外部资源与正式发布；原始技术设计中的动作不等于已执行。

## 启动与登录

1. 在PowerShell运行 `./scripts/Start.ps1`，访问 `http://127.0.0.1:8000`；管理台 `http://127.0.0.1:8000/admin/`，接口文档 `/docs`。
2. 用户已登录本地管理台。后续登录失效时，运行 `.venv/Scripts/python.exe -m app.admin_cli invite --role admin --name 项目维护者`，本人读取 `work/admin-login-code.txt`，30分钟内一次有效；不要发送登录码。
3. 微信AppSecret仅在管理台“微信与模型接入”的本机密码框填写，留空保留已有密钥。AppID已写入，改变AppID后需重建小程序。当前云模型暂不启用。
4. 修改后端后分别运行 `./scripts/Stop.ps1` 与 `./scripts/Start.ps1`；修改前端后按README重建两端，并刷新网页。

## 学生端人工验收

1. 使用虚构信息咨询“我是人工智能学院2025级学术学位硕士，中期考核登记表在哪里下载？”。应定位相应通知，可查看原文并请求打开登记表。
2. 打开“确认我的条件”，修改学院或学历并重新核对。结果需重新分流，不可沿用旧学院条件；未提供的字段保持未知。
3. 在试用说明启用带明确日期的历史回放，再问“我今年读本科二年级，想申请雷军计算机本科生奖学金”。若模型提出候选，核对逐字原话后填入资料面板；候选未确认前不得进入已确认画像。无可靠候选时用表单兜底。
4. 关闭历史回放核对真实日期。部分2026年10月通知已截止，应提示原窗口及无延期依据，不显示仍可报名。
5. 打开历史记录、旧版原文和附件，检查本人可访问、他人不可访问。退出后应撤销当前设备凭证；微信身份可重新登录，匿名身份不能通过新访客找回旧记录。
6. 原生自动电脑控制被安全检查停止，不能据此填写浏览器操作已通过。由用户记录实际浏览器、手机和结果。

## 政策维护、审核、发布与回滚

1. 管理台“政策工作台”从当前版本新建草稿。草稿修改不会影响学生当前回答。
2. 上传DOCX或文本PDF（20MB以内）；新文件默认不进入学生检索。扫描件先完成OCR并人工核验；旧DOC先另存转换，原件保留。
3. 填准确HTTPS原网页、标题和适用范围。文本校正需保留校正依据，不覆盖原始文件。缺失附件明确登记，不能凭经验补齐。
4. 新政策版本若需结构化匹配，填写绑定当前policy_version的规则卡；条件、步骤、材料和截止日期均须对应逐字原文。只支持受限DSL，不执行政策正文中的命令或任意代码。
5. 由合适人员逐项核对版本、范围、日期、材料、规则及正文表格；修改后旧审核失效。当前本地身份审核仅表示试用记录，不能作为学校正式签署。
6. 构建试用候选，核对索引、样例和旧出处。候选构建不会立即发布；使用发布按钮显式切换完整快照，并校验原活动版本，避免并发覆盖。
7. 在发布历史选择曾发布版本回滚，也可回到初始资料版本。受理任务保持原release，旧答案、原件和片段ID可追溯。
8. 正式候选要求已验证学校身份的独立审核。当前没有此类身份，不能靠本地管理员或改数据库制造业务通过。代码发生改变时需重新构建与复核快照，不跨不兼容代码直接回滚数据。

## 内部人工接待闭环

1. 先落实真实接待人。管理员在“成员与接待”给本人确认过的经办人员生成一次性本地邀请，由管理员亲自交付；系统不会代发。
2. 核对经办账号，在接待配置中填写学生可理解的接收方名称并分配账号，确认后启用。当前队列保持关闭。
3. 学生生成摘要，核对内容及接收方，明确同意后提交。回执仅表示已进入本系统队列，尚待经办人员受理。
4. 经办人员在工作台受理并填写实际核实答复；学生可查看进度及答复，未完成的咨询可撤回。重复提交不能建立重复工单。
5. 不把本系统回执说成发到微信、邮件或学校其他工单系统。如另需外部系统，取得接口和明确授权后单独开发。

## 数据保留、备份与恢复

1. 运行 `.venv/Scripts/python.exe -m app.admin_cli retention --days 30` 先预览。仅在责任人确认保留策略后追加 `--apply`；只处理无外部绑定的匿名学生，跳过在途任务、未完成接待、管理和绑定身份。
2. 运行 `.venv/Scripts/python.exe -m app.cli backup` 创建一致数据库、源码、原件、前端和全部已登记发布快照的备份及哈希清单。备份位于被忽略的work，不对外分发学生历史。
3. 运行 `.venv/Scripts/python.exe -m app.cli restore-check`，在隔离目录验证数据库、外键、原件、标准文本、向量、活动指针和恢复源码doctor，不覆盖当前运行目录。
4. 密钥与模型权重不在备份/源码包；在恢复机器由责任人通过受控方式配置密钥，按固定修订恢复模型，再做身份、接待和完整业务验收。不能仅以doctor表示可正式恢复服务。
